# Project: Graphics Conversion Pipeline
# Scope: Graphics downscaling, palette integration, and E2E visual audit.

## Architecture
The graphics pipeline takes the original 16x16 pixel-art sprites from Dandy Dungeon (stored as a base64 PNG in the JS version) and compiles them down to GameBoy-compatible 8x8 2bpp tiles. The output must be integrated into the GBDK build system, and the GameBoy engine must be configured with correct color palettes and sprite transparency.

### Core Rendering Modes:
1.  **Classic DMG Mode (Default)**:
    *   **Aesthetics**: Floor corridors are rendered as White (default color index 0), decorated with sparse, subtle Light Gray dots/tile-cracks to represent texture. Sprites (player, monsters) are dark silhouettes (Dark Gray bodies, Black outlines, White details/eyes) to stand out sharply against the white ground.
    *   **BKG Palette (BGP)**: Maps Color 0 -> White, 1 -> Light Gray, 2 -> Dark Gray, 3 -> Black (standard 0xE4).
    *   **OBJ Palette (OBP0/1)**: Maps Color 0 -> Transparent, 1 -> Dark Gray, 2 -> Light Gray, 3 -> Black.
2.  **Atmospheric Mode (Optional, Compile-Time Toggle `USE_BLACK_FLOOR`)**:
    *   **Aesthetics**: Floor corridors are solid Black. Sprites have bright White bodies, Dark Gray details, and Black outlines.
    *   **BKG Palette (BGP)**: Maps Color 0 -> Black, 1 -> Dark Gray, 2 -> Light Gray, 3 -> White (0x1B).
    *   **OBJ Palette (OBP0/1)**: Maps Color 0 -> Transparent, 1 -> White, 2 -> Dark Gray, 3 -> Black (0xE0).

The workflow is divided into:
1. **De-serialization & Foundation**: Extracting the original 16x16 sheet and building a test harness (`verify_graphics.py`) to generate visual comparison audits.
2. **Mathematical Downscaling**: A Python 3 compiler utilizing font-hinting techniques (sub-pixel grid alignment, feature weight preservation) to scale 16x16 down to 8x8.
3. **Programmatic Selection**: Comparing the mathematical results with programmatic/redrawn designs, choosing the highest-fidelity option per tile, and exporting to GBDK binary format.
4. **Palette & Transparency Integration**: GameBoy hardware palette setup in `src/main.c` supporting macro-conditioned compile-time switching between Classic DMG (default) and Atmospheric Dark modes.
5. **E2E Verification & Audit**: Compiling via `Makefile`, passing `verify_emulator.py`, and executing a 5-point rubric visual audit certified by an independent auditor.

## Interface Contracts
### Graphics Pipeline Output
- **Header file (`src/tiles.h`)**:
  Declares `extern const unsigned char dandy_tiles[32 * 16];`
- **Source file (`src/tiles.c`)**:
  Contains the 512 bytes of compiled 2bpp tile data for all 32 tiles.

### GameBoy Color Palette Configuration
- `BGP_REG`:
  - **Classic DMG (Default)**: Maps 0->White, 1->Light Gray, 2->Dark Gray, 3->Black (0xE4).
  - **Atmospheric Dark (Optional)**: Maps 0->Black, 1->Dark Gray, 2->Light Gray, 3->White (0x1B).
- `OBP0_REG` / `OBP1_REG`:
  - **Classic DMG (Default)**: Maps 0->Transparent, 1->Dark Gray, 2->Light Gray, 3->Black.
  - **Atmospheric Dark (Optional)**: Maps 0->Transparent, 1->White, 2->Dark Gray, 3->Black (0xE0).
- **Macro-Conditioning**: Switched via compile-time `#ifdef USE_BLACK_FLOOR` blocks.

### Visual Audit Sheet (`graphics_audit.png`)
- Generated by `tools/verify_graphics.py`.
- Displays all 32 tiles side-by-side: original 16x16 vs. new 8x8 (upscaled 8x using nearest-neighbor).

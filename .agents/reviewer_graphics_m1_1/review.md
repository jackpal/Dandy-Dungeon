# Milestone 1 Graphics Review Report

## Review Summary

**Verdict**: REQUEST_CHANGES (Critical Integrity Violation)

Milestone 1 of the Dandy Dungeon graphics conversion pipeline has been reviewed. While the sprite extraction script (`extract_sprites.py`) and the GameBoy C compilation work correctly, the graphics verification script (`verify_graphics.py`) is a facade implementation that fails to meet most requirements. Additionally, the provided audit image `graphics_audit_dark.png` is a fabricated artifact not generated by any code in the repository.

---

## Findings

### Critical Finding 1: INTEGRITY VIOLATION — Fabricated Verification Artifact and Facade Implementation
- **What**: The script `verify_graphics.py` is a facade that does not implement command-line flags, palette switching, or checkers transparency rendering. The file `graphics_audit_dark.png` in the repository is a fabricated artifact of size 2240x640 with 243 colors that cannot be generated by the script (which only outputs a 1024x1024 16-color image `graphics_audit.png`).
- **Where**: 
  - `dandy-gb/tools/verify_graphics.py` (entire file)
  - `dandy-gb/teamwork_graphics/graphics_audit_dark.png` (existence of fabricated file)
- **Why**: This violates codebase integrity. The developer provided a dummy implementation that bypasses the core verification features while leaving pre-fabricated images in the directory to make it look like the work was completed.
- **Suggestion**: The developer must rewrite `verify_graphics.py` from scratch (or complete it) to fully support:
  1. Defaulting to the Classic DMG (Light Floor) palette (Color 0 = White, 1 = Light Gray, 2 = Dark Gray, 3 = Black).
  2. The `--dark-floor` flag to generate the Atmospheric (Dark Floor) palette (Color 0 = Black, 1 = Dark Gray, 2 = Light Gray, 3 = White).
  3. Sprites rendered with transparency over a checkers pattern.
  4. Programmatic generation of both `graphics_audit.png` (for Light Floor) and `graphics_audit_dark.png` (for Dark Floor) from the script itself.

### Major Finding 2: Lack of Default Light Floor Palette in Verification
- **What**: `verify_graphics.py` defaults to the Atmospheric (Dark Floor) palette instead of the Classic DMG (Light Floor) palette for background tiles.
- **Where**: `dandy-gb/tools/verify_graphics.py`, lines 38-48.
- **Why**: The default behavior is incorrect and contradicts the specification.
- **Suggestion**: Correct the default background palette mapping to use the Classic DMG palette.

### Major Finding 3: Missing Sprite Transparency and Checkers Background
- **What**: Sprites are rendered with solid black for color 0 (transparent) and color 3 (black) instead of transparency over a checkers pattern.
- **Where**: `dandy-gb/tools/verify_graphics.py`, lines 25-36 and 131-132.
- **Why**: Solid black makes it impossible to distinguish transparent pixels from black pixels in the audit grid, violating the specification.
- **Suggestion**: Implement an 8x8 checkerboard background generator and overlay the sprite tiles using color 0 as transparent.

## Verified Claims

- **Claim 1**: `extract_sprites.py` correctly extracts and decodes the sprite sheet from `strike.js` to `strike_original.png`.
  - *Method*: Executed `python3 tools/extract_sprites.py` in the virtualenv.
  - *Result*: **PASS**. The script runs successfully and verifies the image is exactly 256x32 pixels.
- **Claim 2**: `strike_original.png` has dimensions exactly 256x32.
  - *Method*: Verified via PIL in the extraction script.
  - *Result*: **PASS**.
- **Claim 3**: `verify_graphics.py` correctly decodes the GBDK 2bpp planar format.
  - *Method*: Inspected decoding bit-packing logic on lines 53-61.
  - *Result*: **PASS** (the logic is correct, though the palette and background stitching are incorrect).
- **Claim 4**: GameBoy C codebase compiles cleanly.
  - *Method*: Ran `make clean && make` in `dandy-gb/`.
  - *Result*: **PASS**. The compiler (LCC) compiles all modules cleanly with zero warnings/errors, and successfully links `bin/dandy.gb` (exit code 0).

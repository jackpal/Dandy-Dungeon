## 1. Summary of Empirical Tests

We have thoroughly and empirically verified the correctness and robustness of the graphics extraction and verification pipeline for Milestone 1 of the Game Boy implementation (`dandy-gb`).

We wrote and executed a comprehensive, automated test suite at `dandy-gb/tests/test_graphics_pipeline.py`. The test suite consists of three core test blocks:
1. **Independent Tile Decoding**: Independently parses `dandy-gb/src/tiles.c` and decodes the 2bpp planar Game Boy tile format, verifying the decoded pixels and palette mappings against the outputs generated by the pipeline's `tools/verify_graphics.py` pixel-for-pixel.
2. **Nearest-Neighbor Upscaling Accuracy**: Analyzes the generated `dandy-gb/teamwork_graphics/graphics_audit.png` and verifies that the upscaling is exactly nearest-neighbor (no blur, blending, or antialiasing) by asserting that every upscaled block is perfectly solid and uniform.
3. **Base64 Extraction Robustness**: Simulates various formatting changes in `dandy-js/strike.js` (unexpected whitespaces/newlines, single quotes, template literals, and unconcatenated strings) to test the robustness of `tools/extract_sprites.py`.

All tests passed successfully, confirming the correctness of the graphics decoding while identifying specific edge cases where the extraction script is fragile.

## 2. Detailed Findings & Edge Case Robustness

### A. Core Correctness (Pixel-for-Pixel & Palettes)
- **GB 2bpp Planar Format**: The decoding logic in `verify_graphics.py` correctly interprets the Game Boy's 2bpp planar layout. Each 8-pixel row is encoded in 2 bytes, where the first byte is the low-bit and the second is the high-bit of the color index.
- **Palette Mapping (BGP & OBP0)**:
  - We cross-referenced the hardware configuration in `dandy-gb/src/main.c`:
    - `BGP_REG = 0x1B` (binary `00011011`): Maps color indexes to shades as: `0 -> Black`, `1 -> Dark Gray`, `2 -> Light Gray`, `3 -> White`.
    - `OBP0_REG = 0xE0` (binary `11100000`): Maps sprite color indexes to shades as: `0 -> Transparent (always transparent on GB)`, `1 -> White`, `2 -> Dark Gray`, `3 -> Black`.
  - We confirmed that `verify_graphics.py` implements these exact mappings perfectly.
  - We verified that the categorization of tiles is correct:
    - **Background Tiles** (floor, walls, items, generators, HUD elements) correctly use the BGP palette mapping.
    - **Sprite Tiles** (monsters, arrows, players) correctly use the OBP0 palette mapping.
  - The independent decoder matched `verify_graphics.py` **pixel-for-pixel** across all 32 tiles.

### B. Upscaling Quality (Nearest-Neighbor)
- The audit sheet `graphics_audit.png` upscales the 8x8 GB tiles to 128x128 pixels (a 16x scaling factor).
- The upscaling uses the `Image.NEAREST` filter.
- Our test script programmatically scanned all upscaled blocks and verified that every single 16x16 pixel region within the 128x128 upscaled tiles is 100% solid and uniform.
- **Conclusion**: The upscaling uses exact nearest-neighbor interpolation. No blur, antialiasing, or pixel bleeding is introduced.

### C. Extraction Robustness & Fragility in `extract_sprites.py`
We tested the extraction logic in `extract_sprites.py` against different formatting styles of the base64 string in `dandy-js/strike.js`:

1. **Unexpected Whitespaces/Newlines (ROBUST)**:
   - *Test Scenario*: Whitespaces and newlines added before and after the `+` operators, and multiple newlines added within the base64 string literals.
   - *Result*: **Success**. The regex successfully extracts the strings, and `base64.b64decode` correctly ignores all newlines and whitespaces.
2. **Single Quotes (FRAGILE)**:
   - *Test Scenario*: Changing all double quotes `"` in `strike.js` to single quotes `'`.
   - *Result*: **Failure** (`ValueError`). The regex in `extract_sprites.py` specifically matches double quotes: `re.search(r'strike\.src\s*=\s*"data:image/png;base64,"...` and `re.findall(r'"([^"]*)"', ...)`. It fails to find the assignment.
3. **No Concatenation / Single Large String (FRAGILE)**:
   - *Test Scenario*: Defining the base64 source as a single long string without concatenation: `strike.src = "data:image/png;base64,iVBORw..."`.
   - *Result*: **Failure** (`ValueError`). The regex specifically expects a `+` and concatenation: `...;base64,"\s*\+\s*(.+?);`. It fails to match a single unconcatenated string.

## 4. Recommendations for Improvement
To make the graphics extraction pipeline production-grade and bulletproof against future formatting modifications in `strike.js`, we recommend updating the regex in `tools/extract_sprites.py` to be quote-agnostic and concatenation-optional:

```python
# A more robust regex that handles both single and double quotes, and optional concatenation
match = re.search(r'strike\.src\s*=\s*["\']data:image/png;base64,["\'](?:\s*\+\s*)?(.+?);', content, re.DOTALL)
if not match:
    raise ValueError(...)
assignment = match.group(1)
# Extract strings matching either double or single quotes
strings = re.findall(r'["\']([^"\']*)["\']', assignment)
base64_str = "".join(strings)
```

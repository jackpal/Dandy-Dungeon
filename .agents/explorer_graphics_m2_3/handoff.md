## 2. Logic Chain
- **Decoupled Strategy Architecture**: To accommodate both the baseline standard downscalers (evaluated by Explorer 1) and the custom font-hinting algorithm (designed by Explorer 2), the tool must employ the **Strategy Pattern** to dynamically register and dispatch downscaling algorithms. This isolates the mathematical downscaling logic from image slicing and C code compilation.
- **Integrated Compilation**: The downscaling script should directly compile its 8x8 outputs into `tiles.c` and `tiles.h` to match the exact array format generated by `compile_bmp_sprites.py`. This ensures it acts as a seamless drop-in replacement in the Game Boy build pipeline.
- **Independent Programmatic Auditing**: Rather than relying solely on manual visual checks, we should extend `verify_graphics.py` with an automated `--validate` mode containing programmatic quality assertions (symmetry checks, color count limits, aspect ratio bounding boxes, and outline continuity). This creates an independent auditor that validates the compiler’s output.
- **Robust Adversarial Testing**: Based on the high standards set by `test_graphics_adversarial.py`, the new downscaling tool must have its own dedicated test suite (`test_downscale_sprites.py`) checking file-system permission failures, corrupted/empty input files, non-standard color formats, out-of-range CLI bounds, and extreme parameter values.

## 3. Caveats

- **Layout Invariance**: We assume the original sprite sheet layout (32 tiles of 16x16 in a 256x32 grid) and mapping will remain constant.

## Executive Summary
This report presents the read-only investigation and comprehensive implementation plan for **Milestone 1** of the Dandy Dungeon graphics conversion pipeline. The investigation covers the base64-encoded sprite sheet of the JS version, the GBDK 2bpp tile format structure, the GameBoy build process, and the design of the visual audit verification script `verify_graphics.py`.

Key findings include:
1. The base64 sprite sheet in `dandy-js/strike.js` is a **256x32 pixel PNG** containing **32 tiles of 16x16 pixels** (organized in 16 columns and 2 rows).
2. The GBDK 2bpp format in `dandy-gb/src/tiles.c` contains **32 tiles of 8x8 pixels** (16 bytes per tile, totaling 512 bytes).
3. Each 16x16 sprite from the original game maps **1-to-1** to a single 8x8 GBDK tile. The downscaling is necessary to fit the 20x10 play viewport and 20x8 scoreboard on the 160x144 GameBoy screen.
4. The GameBoy build system integrates these tiles directly via `set_bkg_data` and `set_sprite_data`. The tiles are programmatically generated by `dandy-gb/tools/compile_bmp_sprites.py`.

### 1.2 Format & Dimensions
An analysis of the PNG `IHDR` chunk from the decoded base64 string reveals:
- **Width**: 256 pixels (`0x00000100`)
- **Height**: 32 pixels (`0x00000020`)
- **Format**: PNG (Portable Network Graphics)
- **Grid Layout**: 16 columns and 2 rows of 16x16 pixel sprites (32 sprites total).
  - **Row 0 (Tiles 0–15)**: Background tiles, items, and monsters (Space, Wall, Door, Stairs Up, Stairs Down, Key, Food, Money, Bomb, Ghost, Imp, Golem, Heart, Nest 1, Nest 2, Nest 3).
  - **Row 1 (Tiles 16–31)**: Action and sprite tiles (Arrows in 4 directions, 4 unused padding tiles, Player facing Down, Up, Left, and Right, and 4 unused padding tiles).

### 1.3 Programmatic Extraction & Decoding
The base64 data can be programmatically extracted using regular expressions to gather all double-quoted strings following `data:image/png;base64,` and concatenating them.
Python decoding implementation:
```python
import base64
import re

def extract_and_decode_sprite_sheet(js_file_path):
    with open(js_file_path, "r") as f:
        content = f.read()
    
    # Extract all quoted strings inside strike.src assignment
    matches = re.findall(r'"([^"]*)"', content)
    # The first match is "data:image/png;base64,", the subsequent ones are the base64 chunks
    base64_str = "".join(matches[1:])
    
    # Decode to binary PNG bytes
    png_bytes = base64.b64decode(base64_str)
    return png_bytes
```
This logic is already utilized by the existing tool `dandy-gb/tools/extract_sprites.py`, which outputs the decoded image to `dandy-gb/web/strike_original.png`.

## 2. Investigation of GBDK 2bpp Format (`dandy-gb/src/tiles.c`)

### 2.1 File Structure
The file `dandy-gb/src/tiles.c` contains the compiled GameBoy Color/Classic compatible 2bpp tile representation of the game graphics:
- **Array Name**: `dandy_tiles`
- **Type**: `const unsigned char`
- **Size**: 512 bytes (32 tiles * 16 bytes/tile)
- **Header (`dandy-gb/src/tiles.h`)**:
  Declares `extern const unsigned char dandy_tiles[DANDY_NUM_TILES * DANDY_TILE_SIZE];` where `DANDY_NUM_TILES = 32` and `DANDY_TILE_SIZE = 16`.

### 2.2 GameBoy 2bpp Format Structure
Each GameBoy tile is 8x8 pixels. Each pixel has a color depth of 2 bits (4 possible colors: index 0 to 3).
- **Row Structure**: Each row of 8 pixels is represented by **2 bytes** (planar format):
  - **Byte 1 (Low Byte)**: Holds bit 0 (least significant bit) of the color index for all 8 pixels.
  - **Byte 2 (High Byte)**: Holds bit 1 (most significant bit) of the color index for all 8 pixels.
- **Pixel Order**: MSB-first (Most Significant Bit first). Pixel 0 (leftmost) corresponds to bit 7, while Pixel 7 (rightmost) corresponds to bit 0.
- **Color Index Calculation**: For a pixel at column `x` (0 to 7) in row `y` (0 to 7):
  ```python
  bit0 = (low_byte >> (7 - x)) & 1
  bit1 = (high_byte >> (7 - x)) & 1
  color_index = (bit1 << 1) | bit0
  ```

### 2.3 Mapping: 8x8 GBDK Tiles vs. 16x16 Sprites
There is a **direct 1-to-1 mapping** between the 32 sprites in the original game (16x16 pixels) and the 32 tiles in GBDK (8x8 pixels):
- **Why 8x8?**: The GameBoy's screen resolution is **160x144 pixels**. The Dandy Dungeon viewport displays a **20x10 tile playfield** and a **20x8 tile HUD scoreboard** (total 20x18 tiles).
  - $20 \text{ columns} \times 8 \text{ pixels} = 160 \text{ pixels}$ (fits screen width exactly).
  - $18 \text{ rows} \times 8 \text{ pixels} = 144 \text{ pixels}$ (fits screen height exactly).
  If the tiles were kept at 16x16 pixels, the viewport would require a 320x160 screen, which is impossible on GameBoy hardware. Thus, the entire grid was downscaled from 16x16 to 8x8.
- **Mapping Index**: Sprite `i` (0 to 31) in `strike_original.png` maps directly to Tile `i` in `tiles.c`:
  - `i = col + row * 16` where `col` is in `0..15` and `row` is in `0..1`.

## 3. Investigation of GameBoy Build Process (`dandy-gb/Makefile`)

The build process is managed by `dandy-gb/Makefile` using the GBDK compiler utility `lcc`:
- **Target ROM**: `bin/dandy.gb`
- **Compiler**: `$(GBDKDIR)bin/lcc`
- **Object Files**:
  `OBJS = obj/main.o obj/dandy_core.o obj/gameboy_hal.o obj/levels.o obj/tiles.o`
- **Key Targets**:
  - `all`: Runs `setup`, `levels`, `sprites`, and compiles the final ROM.
  - `setup`: Creates the output directories `obj/`, `bin/`, and `web/`.
  - `levels`: Converts JS levels to C arrays using `tools/convert_levels.py`.
  - `sprites`: Runs `tools/compile_bmp_sprites.py` to generate `src/tiles.c` and `src/tiles.h` from the native 8x8 character art glyph specifications defined inside the python compiler script.
- **WASM compilation (`web`)**: Compiles the core game engine to WebAssembly using Emscripten (`emcc`) to run in web browsers.

## 4. Verification Script Design (`tools/verify_graphics.py`)

The verification script `verify_graphics.py` is a Python 3 tool that creates a side-by-side visual audit sheet (`graphics_audit.png`) comparing the original 16x16 sprites and the compiled GBDK 8x8 tiles.

### 4.1 Functional Design & Architecture
1. **Load Reference Image**: Load `dandy-gb/web/strike_original.png` (dimensions 256x32).
2. **Parse Compiled Tiles**: Read `dandy-gb/src/tiles.c` and extract the 32 arrays of 16 bytes representing the GBDK tiles.
3. **Decode GBDK Tiles**: Convert each 16-byte planar chunk into an 8x8 pixel array of color indices.
4. **Color Mapping & Palettes**:
   - **Background Palette (BGP)**: Used for tiles 0–8, 12–15.
     - Index 0: Black (`#000000`)
     - Index 1: Dark Gray (`#555555`)
     - Index 2: Light Gray (`#AAAAAA`)
     - Index 3: White (`#FFFFFF`)
   - **Sprite Palette (OBP0)**: Used for tiles 9–11, 16–19, 24–27.
     - Index 0: Transparent (rendered on a solid Dark Blue `#1e1e3f` background for contrast)
     - Index 1: White (`#FFFFFF`)
     - Index 2: Dark Gray (`#555555`)
     - Index 3: Black (`#000000`)
5. **Upscaling**:
   - Original 16x16 tiles are upscaled **8x** using nearest-neighbor to **128x128 pixels**.
   - GBDK 8x8 tiles are upscaled **16x** using nearest-neighbor to **128x128 pixels** so they can be compared at the same physical size.
6. **Arrangement & Output**: Create a 1200x1440 pixel canvas containing a 4x8 grid of 300x180 pixel cells. Each cell displays:
   - Tile Index and Name.
   - Original upscaled 128x128 tile (on the left).
   - GBDK upscaled 128x128 tile (on the right).
   - Output saved to `dandy-gb/graphics_audit.png`.

### 4.2 Pseudocode for `verify_graphics.py`
```python
import os
import re
import base64
from PIL import Image, ImageDraw, ImageFont

# Tile Names Mapping
TILE_NAMES = {
    0: "SPACE", 1: "WALL", 2: "DOOR", 3: "UP_STAIRS", 4: "DOWN_STAIRS",
    5: "KEY", 6: "FOOD", 7: "MONEY", 8: "BOMB", 9: "GHOST",
    10: "DEMON", 11: "GOLEM", 12: "HEART", 13: "NEST_1", 14: "NEST_2",
    15: "NEST_3", 16: "ARROW_DN", 17: "ARROW_UP", 18: "ARROW_LF", 19: "ARROW_RT",
    24: "PLAYER_DN", 25: "PLAYER_UP", 26: "PLAYER_LF", 27: "PLAYER_RT"
}

# Palettes
COLOR_WHITE = (255, 255, 255)
COLOR_LIGHT_GRAY = (170, 170, 170)
COLOR_DARK_GRAY = (85, 85, 85)
COLOR_BLACK = (0, 0, 0)
COLOR_SPRITE_BG = (30, 30, 60) # Dark Blue for sprite transparency contrast

def parse_tiles_c(tiles_c_path):
    with open(tiles_c_path, "r") as f:
        content = f.read()
    
    # Extract hex byte values
    hex_bytes = re.findall(r'0x[0-9A-Fa-f]{2}', content)
    bytes_data = [int(h, 16) for h in hex_bytes]
    
    # Group into 32 tiles of 16 bytes each
    tiles = []
    for i in range(32):
        tiles.append(bytes_data[i*16 : (i+1)*16])
    return tiles

def decode_2bpp_tile(tile_bytes, is_sprite):
    img = Image.new("RGB", (8, 8), COLOR_SPRITE_BG if is_sprite else COLOR_BLACK)
    pixels = img.load()
    
    for y in range(8):
        low_byte = tile_bytes[2 * y]
        high_byte = tile_bytes[2 * y + 1]
        for x in range(8):
            bit0 = (low_byte >> (7 - x)) & 1
            bit1 = (high_byte >> (7 - x)) & 1
            color_idx = (bit1 << 1) | bit0
            
            # Map index to RGB
            if is_sprite:
                if color_idx == 0:
                    continue # Keep dark blue background
                elif color_idx == 1:
                    color = COLOR_WHITE
                elif color_idx == 2:
                    color = COLOR_DARK_GRAY
                else:
                    color = COLOR_BLACK
            else:
                if color_idx == 0:
                    color = COLOR_BLACK
                elif color_idx == 1:
                    color = COLOR_DARK_GRAY
                elif color_idx == 2:
                    color = COLOR_LIGHT_GRAY
                else:
                    color = COLOR_WHITE
            
            pixels[x, y] = color
    return img

def main():
    # 1. Load original spritesheet
    ref_path = "dandy-gb/web/strike_original.png"
    ref_img = Image.open(ref_path) # 256x32 pixels
    
    # 2. Parse tiles.c
    tiles_data = parse_tiles_c("dandy-gb/src/tiles.c")
    
    # 3. Setup audit canvas (1200x1440 for 4x8 grid of 300x180 cells)
    audit_canvas = Image.new("RGB", (1200, 1440), (18, 18, 18))
    draw = ImageDraw.Draw(audit_canvas)
    
    # 4. Process all 32 tiles
    for i in range(32):
        col_idx = i % 4
        row_idx = i // 4
        cell_x = col_idx * 300
        cell_y = row_idx * 180
        
        # Determine if it's a sprite tile
        is_sprite = i in [9, 10, 11] or (16 <= i <= 19) or (24 <= i <= 27)
        
        # Crop original 16x16 tile
        orig_col = i % 16
        orig_row = i // 16
        orig_box = (orig_col * 16, orig_row * 16, (orig_col + 1) * 16, (orig_row + 1) * 16)
        orig_tile = ref_img.crop(orig_box)
        orig_upscaled = orig_tile.resize((128, 128), Image.NEAREST)
        
        # Decode & upscale GBDK tile
        gb_tile = decode_2bpp_tile(tiles_data[i], is_sprite)
        gb_upscaled = gb_tile.resize((128, 128), Image.NEAREST)
        
        # Paste onto audit canvas
        audit_canvas.paste(orig_upscaled, (cell_x + 10, cell_y + 40))
        audit_canvas.paste(gb_upscaled, (cell_x + 150, cell_y + 40))
        
        # Draw labels
        name = TILE_NAMES.get(i, f"PADDING_{i}")
        label = f"Tile {i}: {name}"
        draw.text((cell_x + 10, cell_y + 10), label, fill=COLOR_WHITE)
        draw.text((cell_x + 10, cell_y + 172), "Original (16x16)", fill=COLOR_LIGHT_GRAY)
        draw.text((cell_x + 150, cell_y + 172), "GBDK (8x8)", fill=COLOR_LIGHT_GRAY)
        
        # Draw cell separator outlines
        draw.rectangle([cell_x, cell_y, cell_x + 300, cell_y + 180], outline=(40, 40, 40), width=1)
        
    # Save the audit sheet
    audit_canvas.save("dandy-gb/graphics_audit.png")
    print("Visual audit sheet generated successfully at dandy-gb/graphics_audit.png!")

if __name__ == "__main__":
    main()
```

This design provides a precise, automated, and visually clean audit sheet that will allow the downstream implementer/auditor to instantly verify the graphics pipeline results.
